
---

✨ 1. Project Brief  
👉 Startpunkt — definiert Problem, Ziel und Kernfunktionalität

Ich entwickle eine [Produkttyp]-Anwendung namens [Produktname] für [Zielgruppe].

Das Hauptziel ist: [Problem / Nutzen].

Kernfunktionen:
- [Feature 1]
- [Feature 2]
- [Feature 3]

Erstelle daraus ein klares, prägnantes Project-Brief-Statement (max. 3 Sätze).

---

✨ 2. Sitemap  
👉 Erstellt die vollständige Struktur der App (alle Seiten + Bereiche)

Basierend auf dem Project Brief, erstelle eine vollständige Sitemap.

Anforderungen:
- Alle Hauptseiten und Unterseiten enthalten
- Klare Hierarchie (Baumstruktur mit Einrückung)
- Logische Gruppierung (z. B. Auth, App, Settings)
- Decke eine vollständige App ab, inkl.:
  - Authentifizierung
  - Hauptfunktionen
  - Detailseiten
  - Einstellungen
  - Onboarding / Empty States (falls sinnvoll)

Nur strukturierter Text, keine Erklärungen.

---

✨ 3. Seitenliste  
👉 Extrahiert alle Screens — verhindert, dass du Seiten vergisst

Basierend auf der Sitemap, erstelle eine vollständige Liste aller einzelnen Seiten (Screens).

Anforderungen:
- Jede Seite einzeln auflisten (flache Liste)
- Eindeutige, konkrete Namen
- Auch Zustände berücksichtigen, wenn sie eigene Screens sind (z. B. "Empty Dashboard", "Error State")

Keine Gruppierung, nur Liste.

---

✨ 4. Globales UI-System  
👉 Definiert das Layout-System für Konsistenz über alle Seiten

Definiere ein globales UI-Layout-System für die gesamte Anwendung.

Beschreibe:
- Hauptlayout (z. B. Topbar, Sidebar, Content Area)
- Wiederkehrende Komponenten (z. B. Navigation, Modals, Listen, Formulare)
- Grundstruktur von Seiten (z. B. Header + Content + Actions)

Nur strukturelle Beschreibung, keine visuellen Details.

---

✨ 5. Kontext fixieren  
👉 Sorgt dafür, dass alle folgenden Wireframes konsistent bleiben

Nutze ab jetzt folgenden festen Kontext für alle weiteren Antworten:

- Project Brief
- Sitemap
- Seitenliste
- Globales UI-System

Halte dich strikt daran und bleibe konsistent über alle Seiten hinweg.

---

✨ 6. Wireframe-Standard setzen (einmal!)  
👉 Definiert die Regeln für ALLE folgenden Wireframes

Nutze ab jetzt folgenden Wireframe-Standard für alle Seiten:

Erstelle einen detaillierten Wireframe für die Seite: [Seitenname]

Kontext:
- Verwende das globale UI-Layout-System
- Halte strikte Konsistenz mit anderen Seiten
- Nutze wiederkehrende Komponenten (z. B. Topbar, Sidebar, Listen, Formulare)

Anforderungen:
- Nur Struktur und Inhalte
- Von oben nach unten
- Keine Farben, kein Styling, keine visuellen Beschreibungen

Wichtige Regeln:
- Verwende klare, reale UI-Muster (keine generischen Platzhalter)
- Jede Sektion muss funktional sinnvoll sein
- Vermeide doppelte oder redundante Bereiche

Für jede Sektion beschreiben:
- Section Name
- Purpose
- Elements (konkrete UI-Elemente)

Zustände berücksichtigen:
- Standard State
- Empty State (wenn relevant)
- Loading State (wenn relevant)
- Error State (wenn relevant)

Format:

[Seitenname]

- Section: [Name]
  - Purpose:
  - Elements:

- Section: [Name]
  - Purpose:
  - Elements:

- States:
  - Empty:
  - Loading:
  - Error:

Wireframe für: Dashboard

Optional (mehrere Seiten gleichzeitig):

Erstelle Wireframes für folgende Seiten:
- Dashboard

---

🧠 Wichtige Regeln für maximale Qualität

- Nach Sitemap & Seitenliste prüfen → hier passieren die meisten Fehler  
- Wireframes NICHT alle auf einmal generieren → Qualität sinkt  
- Core Pages zuerst (Dashboard, Hauptfeatures)  
- Dann Secondary Pages (Settings, Auth, etc.)
